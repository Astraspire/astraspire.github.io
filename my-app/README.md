# Astraspire Resume & Portfolio Site

Personal portfolio / resume site for **Danny Fetter**. A single-page React + Vite app that renders the resume (summary, technical skills, projects as an AI-progression timeline, education) plus two extra tabs: **AI Systems** (agentic-workflow design, prompt engineering, and a Python runtime identity filter) and the live **AI Memory Controller**.

The site is authored entirely in `src/` and deployed from a Vite production build (see Build / Deploy below). Nothing under the repo root (`index.html`, `assets/`, `vite.svg`) is meant to be hand-edited — those are generated by the build.

## Tech Stack

- **React 19** — UI/components (`my-app/src/App.jsx`, `main.jsx`)
- **Vite 7** — build tool / dev server
- **@mui/material 7 + @emotion** — component library / theming primitives
- **Theme system** — CSS custom-property design tokens (light: white/resume-match + solar accents; dark: solarized palette), toggled via a floating sun/moon button that persists the choice in `localStorage`.

## Project Highlights (what's on the site)

- **Portfolio picture + downloadable resume** — a PDF/DOCX dropdown in the top nav triggers native file downloads.
- **AI-progression timeline** — projects shown chronologically with an "ai info" hover badge documenting the degree of AI usage per project.
- **AI Systems tab** — automated personalization setup, a calculus-tutoring agentic workflow, prompt-engineering/identity pillars, and the Python runtime identity filter.
- **AI Memory Controller** — a local RAG memory tool (vector similarity retrieval) that audits, ranks, and recalls prior context into system prompts.

## Getting Started

Requires **Node.js 18+**. This folder (`my-app/`) holds the Vite/React **source** only — it is not the deployable site by itself.

```bash
# install dependencies (once)
npm install

# start the dev server (with hot reload) at http://localhost:5173
npm run dev

# build a production bundle
npm run build
```

## Build / Deploy Workflow (important)

The build writes to the **repo root** (one level up from `my-app/`), not into `my-app/dist/`:

```
cd my-app && npm run build
```

`my-app/vite.config.js` sets:

```js
build: {
  outDir: '../',          // output to the repo root
  emptyOutDir: false,    // does NOT wipe the root — stale hashed files remain
  assetsDir: 'assets',
}
```

Because `emptyOutDir: false`, every build **adds** new hashed files (e.g. `assets/index-<hash>.js`) but **does not delete** old ones. After each build you must manually prune the stale hashed JS/CSS, plus any superseded source-derived files, from the repo root so GitHub Pages doesn't serve dead links. See `../AgentPlan-docs/REPOSITORY_MAP.md` §4 for the stale-asset tracking checklist.

**Do not hand-edit** the generated root `index.html`, root `assets/`, or root `vite.svg`. Edit `my-app/src/`, rebuild, then sync.

## Deploy (GitHub Pages)

This repo is configured for **GitHub Pages** (served from the repo root). After building, commit the updated root `index.html` + `assets/` + `vite.svg` to the deployment branch. The site uses relative paths (`base: './'`) so links resolve under a GitHub Pages subpath.

## Editing guidance

- **Content / components** → `my-app/src/App.jsx` (single source of truth for resume text).
- **Visual styling** → `my-app/src/App.css` (the token-driven design system; add theme tokens and per-class styles here).
- **Global boilerplate** → `my-app/src/index.css` (keep neutral — let `App.css` own styling).
- **Source assets** → `my-app/src/assets/` (`dannyFetter-*` naming convention: e.g. `dannyFetter-resume2026.pdf`, `dannyFetter-2026portfolioPicture.jpg`).
- **Binary imports** → import PDF/DOCX with a `?url` suffix so Vite emits a string URL instead of choking on the binary (see the import note at the top of `App.jsx`).
